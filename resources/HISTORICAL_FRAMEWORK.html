Java test framework documentation

An earlier guide to organizing web application tests with Java, Selenium WebDriver, Cucumber, JUnit, and Maven. It shows how browser setup, readable scenarios, and reusable page actions fit together.

Open documentation PDF

Framework structure

  • DriverFactory: creates WebDriver instances for the selected browser and closes them after use.
  • SetupTest: reads configuration and manages browser setup and cookies, including a described Safari workaround.
  • TestRunner: configures Cucumber execution, hooks, and scenario selection through tags.
  • Step definitions: connect Gherkin scenarios to Java test actions.
  • Page objects: keep page-specific interactions in a dedicated class.
  • Maven: manages dependencies, compiler settings, and test execution plugins.

Configuration and browser support

The guide separates browser choice, application URL, and scenario tags into config.properties. It lists Chrome, Firefox, Edge, and Safari as browser options. These are documented options; this addition does not claim a verified run on each browser.

Example workflow

The Learnmore example describes a video-playback check: open the page, locate the video, click play, and verify playback. Its page object exposes methods for thumbnail visibility, clicking play, and checking playback. The Java examples contain implementation placeholders.

What this work demonstrates

Framework organization, separation of responsibilities, reusable test steps, configurable execution, and technical documentation that explains how another tester can work with the structure.

The guide also discusses parameterization, assertions, naming conventions, and logging/reporting as recommended practices. It does not include saved test reports or prove that those recommendations were all implemented.
